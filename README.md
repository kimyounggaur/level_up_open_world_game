# 레벨업 음악이론 오픈월드 (가칭 '음악 마을')

걸어 다니며 음악이론을 '배치'로 익히는 2D 탑다운 게임입니다. 설계서(`docs/design/open-world-remake-design-v0.1.md`)를 단계별로 구현하고 있고, 지금은 **범위 A(0–5단계: 음악 마을 완성)**, 6단계, 7단계(7-1 계단밭부터 7-8 교재 대조까지), 8단계의 8-1(출처·권리 대장), 8-2(문구 재검토·개인정보 흐름), 8-3(기준 기기 전체 점검의 자동 부분), 8-4(용량과 불러오기 시간 맞추기), 8-5(공개 조건 점검), 8-6(운영 절차)를 자동 점검까지 통과한 상태입니다(아래 '지금 상태'). 전달 전의 전체 점검(자동 점검 전부와 실제 Chrome 흐름 시험 35개 파일 전체. `docs/approvals.md`의 '최종 점검')도 마쳤습니다. 첫 공개 조건 G2는 사람이 해야 하는 일이 남아 있어 통과로 적지 않았고, 지금 정식 공개 점검은 빌드를 막고 있습니다.

## 실행

Node 22 이상이 필요합니다(개발은 Node 22.23, npm 10.9에서 했습니다).

```sh
npm ci
npm run dev        # 개발 서버
npm run build      # 콘텐츠 검사 + 형 검사 + 빌드(dist/)
npm run preview    # 빌드 결과 열어 보기
npm run build:release # 정식 공개 빌드(dist-release/). 공개 점검(check:release)이 막으면 만들지 않는다. 지금은 막는다
```

- **미리보기 채널(기본)**: 검수 전 콘텐츠도 '검수 전' 표지와 함께 열립니다. 이 채널에서만 `window.__game`으로 상태를 읽을 수 있고, 흐름 시험이 이것을 씁니다.
- **정식 공개 채널**: `VITE_RELEASE_CHANNEL=release npm run build`. 검수가 끝나지 않은 과제는 '준비 중'으로 두고, 공개 승인이 안 된 발견 요소는 목록에 올리지 않습니다(결정 D-12). 공개 호스팅에 올리는 것은 `npm run build:release`가 만드는 `dist-release/`이고 호스팅이 지킬 조건(압축, 캐시, 보안 머리말)은 `docs/hosting.md`에 있습니다.

## 점검

```sh
npm run verify     # 의존 규칙 → 콘텐츠 검사 → 형 검사 → 단위 시험(약 2~2.5분)
npm run build:world # 월드 바닥 조각, 지도, 사물 아틀라스를 다시 굽는다(world-src가 바뀌었을 때, 약 15초). check:world는 낡았는지만 본다
npm run ensemble   # 광장 합주 대표 조합 12가지를 악보에서 점검해 표로 보여 준다(check:ensemble은 문제가 있으면 실패한다)
npm run roadsight  # 길 위의 볼거리 간격(규칙 1)·막다른 길(규칙 2)·걷는 시간을 점검해 보고한다(check:roadsight은 규칙을 어기면 실패한다)
npm run ledger     # 출처·권리 대장의 권리 현황(그림·소리·글꼴·외부 코드와 콘텐츠의 미확인 수)을 보여 준다. 대장과 실제의 어긋남은 validate가 잡는다. build:notices는 제3자 고지 파일을 다시 만들고 check:notices는 낡았는지 본다
npm run check:release # 정식 공개 점검: 열리는 과제 수, 권리 미확인 대장 항목, 내용 잠금, 막다른 길 끝(공개 채널)을 센다. 막는 것이 있으면 1로 끝난다(지금은 막는다). 통과해도 G2의 통과가 아니고 사람이 해야 하는 일의 목록을 늘 함께 낸다
npm run lock:content # 정답 기준을 고친 뒤(과제 파일의 contentVersion을 올린 뒤) 내용 잠금 content/content-lock.json에 기록한다. check:lock은 견주기만 한다. 절차는 docs/operations.md
npm run copy       # 화면에 나오는 한글 문구를 W-9·7.6 규칙에 대 보고 걸린 것을 보여 준다. `npm run copy -- --deck <경로>`는 사람이 읽는 문구 검수표를 만든다(저장소 밖 경로를 권한다). check:copy는 칭찬·능력·나이를 말하는 말이 걸리면 실패한다
npm run build && npm run test:flow
                   # 실제 Chrome(헤드리스)으로 도는 흐름 시험. /usr/bin/google-chrome이 필요하다(CHROME_PATH로 바꿀 수 있다). 전체(35개 파일 598개)는 이 환경에서 약 110분
```

`FLOW_HOSTED=1`을 붙이면 흐름 시험이 호스팅 조건(보안 머리말, 캐시, gzip)을 보내는 시험 서버로 열고, 내용 보안 정책이 막은 요청이 있으면 시험을 실패시킵니다(`docs/hosting.md`). 흐름 시험은 한 파일씩 돌릴 수도 있습니다: `npx vitest run --config vitest.flow.config.ts tests/flow/<파일>`. 크롬 두 개를 동시에 돌리면 느린 화면에서 시간 때문에 실패할 수 있으니 한 번에 하나만 돌립니다. 작업대 조작 막대 측정(`devices.flow.ts`)은 기본이 대표 네 화면이고, `BARS_ALL=1`을 붙이면 아홉 화면 전부를 잽니다(약 9분).

## 구조

| 폴더 | 내용 |
|---|---|
| `src/domain` | 음악 코어(음, 박자, 판정기, 과제 세션, 저장 상태). 시계·난수·화면·저장소를 직접 쓰지 않는다 |
| `src/audio` | 소리(Tone.js): 소리 장치, 악기 음색, 믹서, 재생기, 세계 소리와 두 시계 |
| `src/platform` | 브라우저 쪽 어댑터: 저장소, 주소 길(router), 사용 기록, 월드와 화면의 다리(bridge) |
| `src/world` | 월드 그리기(Phaser): 바닥 조각, 사물, 설치물 층, 등불, 발견 표식, 잔치 층 |
| `src/ui` | 화면(Preact): HUD, 과제 패널, 설치물 패널, 수첩, 설정 |
| `src/app` | 위를 묶는 조립 |
| `content/` | 과제, 설치물, 지역, 발견 요소, 출처·검수 대장(JSON) |
| `world-src/`, `tools/` | 월드 원본(`regions/*.tmj` Tiled 지도의 사물 층, `sprites/*.svg` 사물 그림)과 빌드 도구(바닥 조각, 사물 아틀라스), 콘텐츠 검사, 의존 규칙 검사. 사물을 더하는 방법은 `docs/world-source.md` |
| `tests/unit`, `tests/flow` | 단위 시험, 실제 Chrome 흐름 시험 |
| `docs/` | 설계서, 결정 목록(`decisions.md`), 단계별 승인·검증 기록(`approvals.md`), 개인정보 흐름(`privacy-flow.md`), 호스팅 조건(`hosting.md`), 운영 절차(`operations.md`), 첫 공개까지 사람이 할 일의 목록(`human-pending.md`), 기기 손 점검표(`device-checklist.md`), 용어(`glossary.md`), 참고(`references.md`) |

의존 규칙(`npm run check:deps`): domain은 domain만, audio와 platform은 domain, world는 domain·audio·platform, ui도 domain·audio·platform, app은 무엇이든. world와 ui는 `WorldBridge`로만 서로 안다.
