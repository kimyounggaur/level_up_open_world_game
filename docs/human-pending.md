## 들어서 확인할 것 (소리)
- **음색 듣기(D-5)**: 합성 음색 20개가 악기답게 들리는지.
- **코드가 만든 소리의 승인**: 광장 합주(여섯 성부, 성부마다 층 0–3), 지역 바탕 소리, 정거장 서명 소리, 소리 조각, 놀이 악기의 음과 가락. 사람이 듣고 승인한 뒤 `content/sources/asset-ledger.json`의 `snd.music.world-parts`에서 `rights`를 `own`(또는 `licensed`)으로 고치고 `gate`를 지우고 `checkedOn`을 적는다. 이 항목이 `unconfirmed`인 동안 `check:release`와 `build:release`가 막는다(D-295).
- **대표 조합 12가지를 들어 통과**: 녹음 열두 개가 `docs/verification/ensemble-audio/`에 있다. 합주의 소리 크기와 어울림도 귀로 판단한다.
- 가락·달리는 음·꾸밈음은 이 구현이 자동으로 만든 임시 판이라 사람의 음악 검수가 필요하다.

## 기기와 화면 (손 점검표 51개 항목 — `docs/device-checklist.md`)
- 기준 기기 3종을 정한 뒤 표를 채운다. 그룹: S 소리, T 터치, R 화면 회전, N 노치와 홈 막대, P 선명도와 프레임(P3 프레임 속도: PC 60 fps, 기준 태블릿 30 fps 이상, P4 10분 사용·배터리, P5 그림 메모리, P6 느린 회선에서 처음 열기와 두 번째 방문), F 글꼴, A 접근성, V 저장과 내려받기.
- 실제 아이폰의 무음 스위치와 소리 깨우기(S7, S8), 헤드폰·작은 스피커로 들은 자연음과 타악(S10), 잔치 열기 뒤의 기다림(S11).
- **작은 휴대폰(360×640 세로, 640×360 가로 등)에서는 작업대의 조작 막대가 월드를 거의 또는 완전히 덮습니다**(D-288). 쓸 만한지 T5·T12로 사람이 보고, 고치는 일을 시작할지 정한다.

## 문구
- `npm run copy -- --deck <경로>`로 만드는 문구 검수표를 사람이 읽고 7.6·W-9에 맞는지 판단한다. 기계는 칭찬·능력·나이를 말하는 말 0건(한글 문구 3,284개)까지만 확인했다. 사람이 판단할 후보: '어렵다·쉽다', '틱·판본·id', 긴 문장, 실패를 알리는 문구가 시도의 평가처럼 읽히지 않는지.

## 그림과 화풍 (햇살 과슈, D-308–D-311)
- 새 화풍이 이 게임과 수업에 어울리는지, 아이들이 새 캐릭터(보라 베레모, 우쿨렐레)를 자기로 느끼는지 본다(G1 관찰과 함께). 원칙과 바뀐 것은 `docs/art-direction.md`.
- 사용자가 예로 든 상용 게임을 닮았다는 인상이 없는지 사람의 눈으로 다시 본다(이름, 기호, 무늬, 화면 요소를 가져오지 않았다).
- 회색조와 색약 시뮬레이션에서 지역, 등불의 상태, 캐릭터가 바닥과 구분되는지, 실제 기기에서 풀 결과 그림자가 글자·표식을 방해하지 않는지 본다.
- 아직 이전 그림인 것(주민과 잔치 악사, 설치물 층, 놀이 악기, 발견 표식, 강·여울목·다리·늪의 물, 악보 지도, 패널 안의 그림)을 새 화풍으로 칠할지와 순서를 정한다. 이것들은 뜻을 전하는 그림이라 시험과 함께 바꿔야 한다.

## 호스팅과 법률 (실제로 올려 본 적이 없다)
- 실제 호스팅에 올려 응답 머리말(보안 머리말, `content-encoding: gzip`, `cache-control`)이 `docs/hosting.md`대로 나오는지 확인. HTTPS와 HSTS. Safari와 Firefox에서의 내용 보안 정책(지금은 Chrome에서만 확인).
- 접속 분석 끄기, 접속 기록 보관 기간.
- 개인정보 보호법 적용 여부(대상이 어린이일 때 기기 안 저장과 사용 기록 파일이 '처리'인지 등)와 제3자 고지(MIT, 0BSD, OFL)의 형식이 충분한지는 법률 검토가 필요하다. 이 구현은 법률 검토를 하지 않았다.
- 판을 올리고 내려 보기: 이전 배포로 되돌리기, 열어 둔 탭의 동작.

## 공개할 내용을 정하기
- 어떤 과제와 판본을 `published`로 바꿀지. 지금 열리는 과제는 0개이고, 검수·출처·권리 확인이 끝난 것만 바꿀 수 있다(`npm run validate`가 막는다).
- 막다른 길 끝 8곳(village 3, beat-river, bell-grove, key-marsh, scale-trail, staff-hill 각 1)은 가까운 발견 요소가 검수와 권리 확인을 마치고 공개 상태가 되면 채워진다(`npm run check:release`가 곳과 거리를 알려 준다). 또는 그 막음을 풀지 정한다.
- 상태를 바꾸는 곳: 검수 단계는 `content/sources/review-log.json`, 출처는 과제 파일 `sourceRefs[]`, 공개는 과제·판본·발견 요소의 `availability`(`docs/operations.md`의 '사람이 상태를 바꾸는 곳'). 사람이 상태를 바꾸면 사람의 단계가 자동으로 넘어가지 않게 지키던 시험이 실패하는 것이 맞고, 그때 시험의 기대를 새 상태로 고친다.

## 첫 공개를 내는 순서 (기계가 막는 것이 풀린 뒤)
1. `npm run verify`
2. 정답 기준을 고쳤다면 판 번호를 올리고 `npm run lock:content`
3. `npm run build:release` → `dist-release/`를 호스팅에 올린다(`docs/hosting.md`의 조건을 지킨다)
4. 공개 승인(11.1의 9단계)은 사람이 한다
