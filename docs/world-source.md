# 월드 사물 원본: 지도(Tiled)와 그림(SVG)

설계서 6-3 "Tiled로 사물 놓기, 사물을 한 장으로 묶기". 완료 기준은 **사물을 더할 때 코드를 고치지 않는다**이다.

## 사물을 더하는 방법

1. **그림이 새것이면** `world-src/sprites/`에 SVG 한 장을 넣는다. 파일 이름은 `obj-<지역>-<이름>-<변형>.svg`(9.6). 최상위 `<svg>`에 `width`와 `height`(월드 px)가 있어야 한다. 그림은 2배로 구워 아틀라스에 들어간다.
2. **Tiled로** `world-src/regions/<지역>.tmj`를 열고, 사물 층에 점(삽입 > 점)을 찍은 뒤 class와 속성을 적는다. 이름(name)이 사물의 id이고 월드 전체에서 겹치지 않아야 한다.
3. `npm run build:world`를 돌린다. 막힌 칸 표, 바닥 그림자, 누르기 영역, 아틀라스(`public/world/objects.webp`, `objects.json`), 생성 파일이 다시 만들어진다. 길을 막거나 정거장에 닿지 못하게 하면 이 단계에서 문제로 나온다.
4. `npm test`를 돌리면 생성 파일이 낡았는지(`check:world`와 같은 검사)까지 본다.

코드(`src/`, `world-src/*.ts`, `tools/`)는 고치지 않는다. 이 약속은 `tests/unit/world-source.test.ts`의 "6-3 완료 기준" 묶음이 지킨다: 데이터만 더한 원본으로 굽고, 새 사물이 월드 사물, 막힌 칸, 그림자, 누르기 영역, 아틀라스 틀로 나타나는지 본다.

## class와 속성

지도는 월드와 같은 칸이다: 256×192칸, 칸 32 px, 직교(orthogonal). 사물 층(objectgroup)만 읽고, 눈 아이콘으로 감춘 사물과 층은 건너뛴다. 이름이 지역 id인 파일(`village.tmj`, `staff-hill.tmj`, …)은 지역 순서대로, 그 밖의 파일은 이름순으로 뒤에 읽는다. 사물은 읽는 순서와 상관없이 발 위치의 y 순서로 정렬된다.

### 그림 사물 — 점(point) 사물, class = `tree` | `sign` | `prop`

| 속성 | 형 | 기본값 | 뜻 |
|---|---|---|---|
| `sprite` | 글 | (필수) | 그림 이름. 파일 이름에서 `.svg`를 뗀 것 |
| `w`, `h` | 숫자 | 그림 크기 | 월드에서 그려지는 크기(px) |
| `ax`, `ay` | 숫자 | 0.5, 1 | 그림 안의 기준점 비율. 점이 찍힌 곳에 이 지점이 온다. 나무는 가운데(`ay` 0.5), 서 있는 사물은 아래(`ay` 1) |
| `footDy` | 숫자 | 0 | 발이 놓인 점에서 얼마나 아래인가. 겹침 순서(`sortY` = y + footDy)와 막힘 원의 가운데가 된다 |
| `blockR` | 숫자 | 0 | 0보다 크면 발 자리에 이 반지름의 원이 막힌다(줄기) |
| `shadowR` | 숫자 | 0 | 0보다 크면 이 반지름의 그림자 원을 바닥에 굽는다(오른쪽 아래로 (15, 24) 어긋남, 9.1) |
| `station` | 글 | 없음 | 정거장 id. `sign`은 필수 |
| `hitDx`, `hitDy`, `hitW`, `hitH` | 숫자 | 없음 | 정거장의 누르기 영역(놓은 점에서의 거리와 크기). 네 개를 모두 적고 `station`이 있어야 한다 |

- `tree`는 줄기 막힘을 시험이 확인한다(`world-bake.test.ts`). `sign`은 안내 칩이 가리키는 표지판이다. `prop`은 그 밖의 소품(물레방아, 종탑 따위)이다.
- 모르는 속성은 오타로 보고 문제로 잡는다.

### 누르기 영역 — 사각형(rectangle) 사물, class = `hit`

`station` 속성 하나. 사각형이 그대로 정거장의 누르기 영역이 된다. 한 정거장에 영역은 하나만 둔다.

### 막힌 자리 — 사각형 또는 타원 사물, class = `block`

속성 없음. 사각형은 그대로 막히고, 타원은 가로와 세로가 같은 원만 쓴다.

## Tiled로 놓지 않는 것: 징검다리 여울목과 방앗간 웅덩이

6-4와 6-5의 여울목(E1, E2의 물웅덩이와 E3 잔물결 수로의 긴 물웅덩이)은 사물이 아니라 바닥 그림과 막힌 자리라서 지도 파일에 두지 않고 `world-src/outer.ts`의 `FORDS`(정거장 id, x, y, 폭, 높이, 줄 방향 `axis`, 줄의 첫 칸 `laneStart`, 한 박의 길이 `beatPx`, 제방 `levees`)에 있다. 칸(32 px) 경계에 맞춘 사각형이라 그림(`fordSvg`)과 막힌 칸(`fordColliders`)이 같다. 여울목을 옮기거나 더할 때는 `FORDS`와 설치물 파일(`content/installations/`)의 `interactPoint`, 슬롯을 함께 고치고 `npm run build:world`를 돌린다.

- **E1, E2**: 줄은 가로로 여울목 가운데(480×96 px, 한 칸 60 px)에 놓인다.
- **E3(확대형)**: 같은 물웅덩이를 세로로 세운 것이다(`axis: 'y'`, 한 박 480 px, 1 px = 2틱). 물웅덩이는 x 6624–6784, y 672–2656(160×1984 px)이고 줄은 x 6656–6752, y 700–2620(칸 32개, 한 칸 60 px)이다. 줄 왼쪽의 박 번호 띠(44 px)와 오른쪽의 뗏목 표지 띠(32 px)가 같은 물 안에 든다. 박 말뚝은 박 경계마다 5개다.
- **제방(`levees`)**: 강 둑과 물웅덩이 사이에 한 칸(32 px) 폭으로 남는 틈은 둑 색 땅으로 메운다. 통로는 64 px 이상이어야 하고 보이지 않는 벽이 없어야 해서(3.8) 좁은 틈을 길처럼 남기지 않는다. 제방의 그림과 막힌 칸도 같은 사각형에서 나온다. E3에는 둘이 있다: x 6784, y 864–1216과 x 6784, y 2624–2656.

물웅덩이와 제방 위로는 걸어갈 수 없다.

### 방앗간 웅덩이(E4 물레방아, 6-6)

물레방아(지름 480 px, 설계서 4.5)의 바닥도 같은 방식이다. `world-src/outer.ts`의 `MILL_PONDS`(정거장 id, x, y, 폭, 높이, 띠의 첫 칸 `laneStart`, 띠의 왼쪽 `laneX`와 폭 `laneW`, 한 박의 길이 `beatPx`, 박의 수 `beats`, 바퀴 `wheel {cx, cy, r}`)에 한 줄이 있고, 그림(`millPondSvg`)과 막힌 칸(`millPondColliders`, 메모 'E4 방앗간 웅덩이')이 같은 사각형에서 나온다. `world-src/index.ts`가 그림은 `fordSvg()` 다음에, 막힌 칸은 여울목 막힌 칸 다음에 이어 붙인다.

- **자리**: 웅덩이는 x 5696–6400, y 2080–2592(704×512 px, 칸 경계에 맞춤)이다. 동쪽 끝(6400)에서 E4 서는 자리(6450, 2300)까지 50 px이 남고, 순환 길(폭 124, x 6408–6532 근처)과 정거장은 걸어갈 수 있는 땅으로 남는다. 가장 가까운 나무(tree-beat-river-16, tree-beat-river-4)는 웅덩이에서 94 px 이상 떨어져 있다.
- **바퀴**: 중심 (6144, 2336), 반지름 240(x 5904–6384, y 2096–2576). 이 값은 설치물 파일의 `slotMap.wheel`(`cx`, `cy`, `r`)이 정하고 `MILL_PONDS.wheel`은 바닥 물결을 그리는 데만 쓴다. 바퀴 그림은 바닥이 아니라 `WheelLayer`(`src/world/installations/wheelLayer.ts`)가 장면에서 그린다. 바닥에는 물과 박 말뚝만 있다. 못의 길이는 `slotMap.maxStoneCells`(3칸 = 점4분음표)까지다.
- **띠**: x 5760–5856, y 2096–2576(80 px 칸 6개, 한 박 240 px, 2박; 설치물 파일의 `slots` 6개와 `slotMap`의 `ticksPerPx` 6, `cellTicks` 480). 징검다리와 같은 `timelineStones` 규칙(`slotMap.kind`)을 쓰므로 띠의 돌과 바퀴의 못은 같은 초안에서 그려진다.
- **바꾸는 법**: 웅덩이를 옮기면 `MILL_PONDS`와 설치물 파일 `content/installations/inst.beat-river.waterwheel.json`의 `interactPoint`, `slots`, `slotMap.wheel`을 함께 고치고 `npm run build:world`를 돌린다. 어긋나면 `tests/unit/world-mill.test.ts`가 잡는다(칸 경계에 맞음, 바퀴와 띠가 물 안에 듦, 서는 자리와 둘레길은 막히지 않음, 둘레 나무·수로와 한 칸 폭 통로가 없음, 칸마다 그림이 물임).

### 종나무 터(W1–W4, 6-7)

종나무(설계서 4.6)는 바닥을 새로 그리지 않는다. 숲의 풀밭 위에 `BellLayer`(`src/world/installations/bellLayer.ts`)가 줄기·가지·고리·종을 장면에서 그린다. 자리는 설치물 파일의 `slots`(고리 하나가 80×72 px 칸)와 `slotMap`(`kind: 'bellTree'`, 형태, 나무 수, 열 수, 단의 옥타브)이 정하고, 틀은 고리 격자에 이름표 띠(왼쪽 52 px, 위쪽 44 px)를 더한 사각형(`slotBounds`)이다.

- **틀(월드 좌표)**: W1 x 1688, y 2248, 372×332 / W2 x 1528, y 3046, 372×332 / W3 x 928, y 2048, 292×332 / W4 x 304, y 1144, 1204×332(세 그루 빈터). 서는 자리는 설계서의 정거장 표 그대로다(W1 (1900, 2700), W2 (1500, 3500), W3 (1100, 2500), W4 (900, 1600)).
- **나무를 치웠다**: 설치물 층은 사물보다 아래에 그려져서 틀 안에 놓인 나무의 덮개가 가지와 종을 덮고, 나무 줄기는 막힌 자리라서 고리 칸 안에 있으면 지나가며 울리는 화음을 밟을 수 없다. 그래서 `world-src/regions/bell-grove.tmj`에서 틀과 겹친 나무 여섯 그루(`tree-bell-grove-1`, `-8`, `-30`, `-36`, `-47`, `-60`)를 지웠다. 나무는 163그루에서 157그루로, 사물은 181개에서 175개로, 바닥 지문은 `03478a580ad4d588`에서 `bcf1e4ada4252770`으로 바뀌었다.
- **바꾸는 법**: 종나무를 옮기거나 새로 놓으면 설치물 파일의 `interactPoint`, `slots`, `slotMap`을 함께 고치고, 틀과 겹치는 나무를 Tiled에서 지운 다음 `npm run build:world`를 돌린다. 어긋나면 `tests/unit/bell-site.test.ts`가 잡는다(어떤 나무의 덮개도 틀과 겹치지 않음, 모든 고리 칸의 가운데와 네 모서리 안쪽은 걸을 수 있음, 이름표 띠도 걸을 수 있음, 카메라 여유 24 px 안에 줄기가 없음, 검사가 헛돌지 않음).

### 메아리 벽(종나무 숲의 놀이 악기, 6-9c)

놀이 악기 `play.bell-grove.echo-wall`(설계서 3.6)은 서 있는 벽 하나와 그 앞 땅의 돌 다섯 개다. 돌과 소리는 `content/discoveries/bell-grove.json`의 `playInstruments`가 정하고, 이 문서가 다루는 것은 월드 원본에 놓인 **벽 그림과 막힌 자리** 둘이다(돌 그림은 장면의 `PlayLayer`가 그린다). 벽은 (600, 600)에 서 있고 돌은 그 아래 한 줄이다: y 710, x 392·496·600·704·808.

- **놓인 것(`world-src/regions/bell-grove.tmj`)**: 점 사물 `prop-bell-grove-echo-wall`(그림 `obj-bell-grove-echo-wall`, 서는 자리 (600, 612), 아래 가운데 기준, 520×150)과 사각형 `block-bell-grove-echo-wall`(x 360, y 552, 480×48)이다. 그림 원본은 `world-src/sprites/obj-bell-grove-echo-wall.svg`다. 사각형은 벽의 아랫단(y 552–600)만 막고, 돌이 놓인 땅(y 666–754)과 그 아래 걷는 줄은 열어 둔다.
- **나무를 치웠다**: `tree-bell-grove-2`(캐노피 가운데 (731, 588), 줄기 (731, 624))는 벽 그림 위에 얹히고, `tree-bell-grove-16`(캐노피 가운데 (406, 768), 줄기 (406, 804))는 캐노피가 첫 돌(392, 710)을 덮고 줄기가 아래쪽 걷는 줄(y 800)을 막았다. 둘을 지웠다. 나무는 157그루에서 155그루로, 사물은 175개에서 174개(나무 둘을 빼고 벽 하나를 더함)로, 바닥 지문은 `bcf1e4ada4252770`에서 `f1d215145f5ea25a`로 바뀌었다(표지판은 18개 그대로, 그림 사물은 `prop` 1개).
- **돌은 지도 사물이 아니다**: 돌 다섯 개는 Tiled에 놓지 않는다. 막히지도 않고(밟는 것이 놀이다) 그림도 장면이 그리므로, 돌 자리를 바꾸려면 `playInstruments`의 `pads`만 고친다. 벽을 옮길 때만 이 파일의 `prop`과 `block`을 함께 옮기고, 새 벽과 겹치는 나무를 지운 다음 `npm run build:world`를 돌린다.
- **어긋나면**: `tests/unit/discovery-regions.test.ts`가 돌이 놓인 땅이 모두 걸을 수 있는 땅이고 지역 안인지, 벽 가운데는 막히고 돌은 열린 땅인지, 발견 요소 27개와 500 px 이상 떨어졌는지를 잡고, `tests/flow/phase6-play.flow.ts`가 실제 크롬에서 돌 다섯 개를 걸어서 밟는 것을 확인한다.

### 물방울 북(박자 강가의 놀이 악기, 6-9c)

놀이 악기 `play.beat-river.drum`은 (7700, 2200) 둘레의 물바닥에 돌 네 개가 놓인 것이다: 가운데에서 가로·세로로 72 px씩 떨어진 (7628, 2128), (7772, 2128), (7772, 2272), (7628, 2272). 돌과 물바닥은 모두 장면의 `PlayLayer`가 그리므로 월드 원본(Tiled)에 놓인 것은 없다. 그래서 이 악기가 월드 원본에 요구하는 것은 하나, **돌 위에 나무 잎이 얹히지 않게 하는 것**이다.

- **나무를 치웠다**: `tree-beat-river-2`(캐노피 가운데 (7644, 2357), 그림 `obj-beat-river-tree-r90`이라 잎 반지름 90, 줄기 (7644, 2402))의 잎이 넷째 돌(7628, 2272)을 덮었다. 돌은 바닥 바로 위(`PlayLayer`, 깊이 −92000)에 그려져서 사물(발 위치 순서로 쌓이는 나무 잎)보다 늘 아래이므로, 잎이 닿는 돌은 어떤 나무에든 가려진다. 6-9c에서 장면 사진을 눈으로 보다가 찾았고(걸어서 닿는지만 보는 자동 시험은 놓쳤다), 이 나무를 지웠다. 나무는 155그루에서 154그루로, 사물은 174개에서 173개로, 바닥 지문은 `f1d215145f5ea25a`에서 `b78410492900290a`로 바뀌었다.
- **어긋나면**: `tests/unit/discovery-canopy.test.ts`가 놀이 악기의 돌 스물네 개(물방울 북 넷, 나머지 네 악기 다섯씩), 소리 조각과 쪽지 54개, 광장 둘레의 등(7-4 전의 18개와 지금의 36개)이 나무 잎에 가려지지 않는지를 지금 놓인 지도에서 읽어 잡는다. 고치기 전에는 이 돌과 이 나무 한 쌍으로 걸렸고 지금은 통과한다. 나무를 더하거나 악기·발견 요소를 옮길 때 같은 시험이 다시 잡는다. `tests/flow/phase6-play.flow.ts`의 사진 시험은 찍힌 그림에서 돌 하나하나가 쉬는 돌 색으로 보이는지를 한 번 더 본다.

### 계단밭 터(N1–N3, 7-1d)

계단밭(설계서 4.7)도 바닥을 새로 그리지 않는다. 오선 언덕의 풀밭 위에 `TerraceLayer`(`src/world/installations/terraceLayer.ts`)가 줄 돌담, 음자리표 조각상, 등, 덧줄 돌담을 장면에서 그린다. 자리는 설치물 파일의 `slots`(열 하나가 폭 96 px, 열 사이 간격 140 px)와 `slotMap`(`kind: 'staffField'`, 가온 도의 세로 좌표 `c4Y` 1000, 높이 범위 `low`·`high`, `clefs`)가 정하고, 틀은 열 격자에 글자 띠(위쪽 56 px, 왼쪽 64 px)를 더한 사각형(`terraceBounds`)이다. 세 설치물(N1 높은음 계단밭, N2 낮은음 계단밭, N3 가운데 턱)이 같은 밭을 나누어 쓴다: 열의 x는 4352 + 140k(k는 0에서 7), 온음계 한 칸은 48 px(`y = 1000 − 48 × 칸 수`)이다.

- **틀(월드 좌표)**: N1 x 4288, y 248, 1140×872 / N2 x 4288, y 824, 1140×872 / N3 x 4288, y 248, 1140×1448. 서는 자리는 설계서의 정거장 표 그대로다(N1 (4200, 712), N2 (4200, 1288), N3 (4200, 1000)).
- **나무를 치웠다**: 설치물 층은 사물보다 아래에 그려져서 틀 안에 놓인 나무의 덮개가 등과 덧줄 돌담을 덮고, 나무 줄기는 막힌 자리라서 열 안에 있으면 지나가며 울리는 등을 밟을 수 없다. 그래서 `world-src/regions/staff-hill.tmj`에서 틀과 겹친 나무 열세 그루(지도 파일의 나무 번호 1, 3, 4, 5, 8, 9, 10, 11, 15, 16, 17, 18, 22)를 지웠다. 나무는 154그루에서 141그루로, 사물은 173개에서 160개로, 바닥 지문은 `b78410492900290a`에서 `30b3e4eed19f20d1`로 바뀌었다(다음 절의 허수아비 밭이 이 값을 한 번 더 바꾼다).
- **바꾸는 법**: 밭을 옮기거나 새로 놓으면 설치물 파일의 `interactPoint`, `slots`, `slotMap`을 함께 고치고, 틀과 겹치는 나무를 Tiled에서 지운 다음 `npm run build:world`를 돌린다. 어긋나면 `tests/unit/terrace-site.test.ts`가 잡는다(어떤 나무의 덮개도 틀과 겹치지 않음, 틀 안을 16 px 간격으로 훑어도 막힌 점이 없음, 카메라 여유 24 px 안에 줄기가 없음, 검사가 헛돌지 않음).
- **7-4에서 풀었다**: 설계서 3.5의 놀이 악기 '높낮이 미끄럼길' (5000, 300)은 N1과 N3의 틀(가로 4288–5428, 세로 248부터) 안에 들어 돌 다섯 가운데 셋이 틀 안이었고 하나는 걸어서 닿지 않는 자리였다. 7-4에서 틀 밖의 오선 언덕 서쪽 풀밭 (3300, 500)으로 옮겼다(틀의 서쪽 변에서 988 px, D-239). 이 악기의 돌과 바닥은 장면의 `PlayLayer`가 그리므로 월드 원본에는 놓은 것이 없다.

### 허수아비 밭(관찰 O1, 7-1)

관찰 O1(설계서 5.3)은 판정이 없는 풍경이고 정거장이 아니다. 월드 원본에 놓인 것은 `world-src/regions/staff-hill.tmj`의 그림 사물(class `prop`) 여덟이다. 판정도 안내 글도 없이, 걸어서 지나가며 기둥의 방향을 본다.

- **놓인 것**: 밧줄 하나 `rope-staff-hill-middle-line`(그림 `obj-staff-hill-field-rope` 700×44, (3500, 900), `ay` 0.5)과 허수아비 일곱 `scarecrow-staff-hill-p1`…`p7`. `pN`은 보표 위치 N을 맡아 (3500 + 90 × (N − 4), 900 + 48 × (4 − N))에 선다(위치가 하나 오르면 48 px 높이, 90 px 오른쪽). p1–p3은 `obj-staff-hill-scarecrow-up`(기둥이 위로, `ax` 0.4423, `ay` 0.8182, `footDy` 22), p4–p7은 `obj-staff-hill-scarecrow-down`(기둥이 아래로, `ax` 0.5577, `ay` 0.2841, `footDy` 118)이고 두 그림 모두 104×176이다. 그림의 기준점이 허수아비의 머리(음표 머리)라서 점이 찍힌 높이가 곧 음의 높이다. `blockR`가 없어 막지 않는다. 그림 원본은 `world-src/sprites/obj-staff-hill-scarecrow-up.svg`, `-down.svg`, `obj-staff-hill-field-rope.svg`다.
- **규칙은 코드가 아니라 도메인의 함수가 안다**: 음표 기둥의 방향은 `src/domain/staff.ts`의 `stemDirectionOf`(보표 위치로만 정한다: 가운데 줄 아래는 위로, 가운데 줄과 그 위는 아래로)이고, 시험이 놓인 그림이 이 규칙과 같은 방향인지 읽는다.
- **나무를 치웠다**: `tree-staff-hill-13`과 `tree-staff-hill-23`은 덮개가 허수아비를 덮고 줄기가 막은 점이 있어 지웠다. 나무는 141그루에서 139그루로, 사물은 160개에서 166개로(나무 둘을 빼고 그림 사물 여덟을 더함), 바닥 지문은 `30b3e4eed19f20d1`에서 `2a808a0c8b1a31e5`로 바뀌었다(표지판은 18개 그대로, 그림 사물 `prop`은 9개).
- **어긋나면**: `tests/unit/scarecrow-field.test.ts`가 기둥 방향 규칙, 놓인 높이와 간격, 그림의 방향과 그림 속 기둥의 뻗음, 지역 안인지, 나무 덮개와 막힌 점이 없는지, 판정과 연결이 없는지, 검사가 헛돌지 않는지를 잡고, `tests/flow/phase7-terrace.flow.ts`의 O1 시험이 실제 Chrome에서 밭을 걸어 지나가도 모드와 사건이 없음을 확인한다. 허수아비 그림은 자리표시용으로 새로 그린 것이다.

### 음계 길 터(S1–S3, 7-2)

음계 길의 디딤돌 길(T1) 셋은 마을 H4처럼 **돌이 바닥 그림에 구워진다**. 설치물 층(`layer.ts`)은 구워 둔 돌 위에 이름·번호·표식만 올려 그려서(4-1), 돌 그림이 바닥에 없으면 설치물 모드 밖에서는 돌이 아무 데도 보이지 않는다(처음에 이 일을 빠뜨렸다, D-217). 돌 그림은 월드 원본(Tiled)이 아니라 `world-src/stones.ts`가 만든다: `TRAIL_STONE_ROWS`가 줄마다 설치물 id와 첫 돌의 왼쪽 위 모서리와 개수를 적고(돌 81×153, 중심 간격 99), `trailStonesSvg()`가 H4와 같은 모양(모서리 12, 테두리 3, 속 점 반지름 15)으로 그려 바닥 그림의 길 위, 나무 그림자 아래에 얹는다. 속 점의 색은 마을 돌(`STONE_DOTS`)의 풀빛에서 볕빛으로 이어지는 색이다: 돌이 8개이면 H4와 같고, 6개이면 같은 범위에서 고르게 건너뛴다.

- **틀(월드 좌표)**: S1 x 5550, y 4724, 774×153(돌 8개) / S2 x 6250, y 5224, 774×153(돌 8개) / S3 x 6074, y 4974, 576×153(돌 6개). 서는 자리는 설계서의 정거장 표 그대로다(S1 (5400, 4800), S2 (6100, 5300), S3 (6800, 5000)). 표지판은 서는 자리에서 오른쪽 72 px, 위쪽 8 px에 서고 막는 자리(반지름 14)가 있다. S1과 S2는 서는 자리 오른쪽 150 px에서 돌이 시작한다. S3 다섯 음 길은 오른쪽에 박자 강 서쪽 기슭이 바짝 다가와서(처음 놓은 틀 x 6950–7526은 틀 안 표본 40점과 다섯째 돌의 모서리가 강의 막힌 자리에 걸렸다) 서는 자리 **왼쪽**에서 돌이 끝난다. 돌 번호는 어느 쪽이든 왼쪽에서 오른쪽으로 높아지므로 S3는 서는 자리 쪽 끝이 6번이고, 서는 자리에서 왼쪽으로 걸으면 6번 돌부터 밟는다. 돌 크기는 설계서 4.3의 '다른 정거장은 80×150, 간격 100'이 아니라 H4와 같은 81×153, 간격 99이다(9.3의 그림 규격과 맞추려고. 이유와 되돌리는 법은 D-209).
- **나무를 치웠다**: `world-src/regions/scale-trail.tmj`에서 S2 틀과 겹친 나무 둘을 지웠다. `tree-scale-trail-3`은 덮개 가운데가 (6518, 5406)으로 틀의 아래 끝(y 5377)보다 29 px 아래이고 반지름이 90이라, 덮개가 틀 안 61 px까지 올라와 셋째와 넷째 돌의 아래쪽을 덮었다. `tree-scale-trail-10`은 덮개 가운데 (6722, 5292)(반지름 54)가 틀 안이고, 줄기 (6722, 5319)(반지름 15.12)가 다섯째 돌의 오른쪽을 막았다. 나무는 139그루에서 137그루로, 사물은 166개에서 164개로, 걸을 수 있는 칸은 43,106에서 43,118(전체 49,152)로, 바닥 지문은 `2a808a0c8b1a31e5`에서 `fa5d76516369008e`로 바뀌었다. 이어서 돌 그림을 바닥에 구우면서 지문이 `5fe45441172fdf4d`가 되었다(걸을 수 있는 칸과 사물 수는 그대로, 바닥 조각 48장 430 KB).
- **바꾸는 법**: 돌 줄을 옮기거나 개수를 바꾸면 설치물 파일(`content/installations/inst.scale-trail.*.json`)의 `interactPoint`와 `slots`, `world-src/stones.ts`의 `TRAIL_STONE_ROWS`를 함께 고치고, 틀과 겹치는 나무를 Tiled에서 지운 다음 `npm run build:world`를 돌린다.
- **어긋나면**: `tests/unit/scale-trail-site.test.ts` 17개가 잡는다: 틀과 서는 자리와 돌 간격(99 px), 틀이 지역 안이고 서로 겹치지 않음(줄 사이 64 px 이상), 박자 강 물가에서 128 px 이상(S1 825, S2 487, S3 650), 어떤 나무의 덮개도 틀과 겹치지 않음, 틀 안을 16 px 간격으로 훑어도 막힌 점이 없음, 돌마다 가운데와 네 모서리 안쪽이 걸을 수 있음, 틀 둘레 24 px 안에 줄기 없음, 서는 자리에서 모든 돌 가운데까지 길 찾기로 닿고 우회가 직선의 1.35배 안임, 표지판의 자리와 그림이 돌을 가리지 않음, 구운 돌 줄이 설치물 파일의 slots와 같고 바닥 그림에 돌마다 모양과 점이 있음, 검사가 헛돌지 않음. 실제 Chrome `tests/flow/phase7-scale-trail.flow.ts`의 '걷는 중에도 돌이 보인다' 셋이 설치물 모드 밖에서 찍은 화면에서 돌마다 속 점이 보이는지를 읽는다.

### 건반 늪 터(K1–K4, 7-3)

건반 늪의 정거장 넷은 월드 원본(Tiled)이 아니라 코드가 바닥 그림에 굽는다. 건반 다리 셋(T6: K1 건반 다리, K2 음정 밧줄, K3 제자리표 다리)은 북쪽 기슭에 붙은 늪 웅덩이 위의 널다리이고, 반음 계단(K4, T1)은 음계 길처럼 디딤돌이다. 다리는 `world-src/keyBridge.ts`(`KEY_BRIDGE_SITES`, `poolOf`, `keyBridgesSvg`, `keyBridgeColliders`, `keyBridgeWalkable`)가, K4의 돌은 `world-src/stones.ts`(`TRAIL_STONE_ROWS`의 K4 줄 둘)가 만든다. 설치물 층(`src/world/installations/keyBridgeLayer.ts`)은 구워 둔 널 위에 이름·표식·이름표·밧줄·깃발만 올려 그려서(4-1), 널 그림은 걷는 중에도 보인다.

- **틀과 널 줄(월드 좌표)**: K1 틀 x 1760, y 5132, 1080×448 / K2 x 912, y 5532, 576×448 / K3 x 2912, y 5632, 576×448 / K4 x 900, y 4560, 675×336. 다리의 틀은 널 줄에 위쪽 띠 168 px(이름표·밧줄·깃발·표지판 악보)와 아래쪽 띠 40 px를 더한 것이다. 널 줄(가장 낮은 흰 널의 왼쪽 위 모서리와 크기)은 K1 (1760, 5300) 1080×240(흰 널 15장 C4–C6, 검은 널 10장), K2 (912, 5700) 576×240(흰 널 8장, 검은 널 5장), K3 (2912, 5800) 576×240(흰 널 8장, 검은 널 5장)이다. 흰 널은 72×240, 검은 널은 44×150이고 흰 널 경계에 가운데를 맞추어 윗변을 흰 널과 같게 둔다. 널 자리는 설치물 파일(`content/installations/inst.key-marsh.*.json`)의 `slots`와 `slotMap`(`kind: 'keyBridge'`, `lowMidi` 60, `whiteCount`)이 정한다. 서는 자리(`interactPoint`)는 설계서 3.5 그대로다(K1 (2300, 5100), K2 (1200, 5500), K3 (3200, 5600), K4 (800, 4700)).
- **늪 웅덩이와 걸을 수 있는 자리**: 웅덩이는 널 줄 둘레에 옆으로 48 px, 아래로 48 px 이상 여유를 두고 칸(32 px) 경계로 바깥으로 맞춘 사각형이고, 윗변은 널 줄 윗변을 칸으로 올림한 기슭이다(널이 기슭에 걸터앉는다). K1 (1696, 5312) 1216×288, K2 (864, 5728) 672×288, K3 (2848, 5824) 704×288. 웅덩이는 막힌 칸이고(`keyBridgeColliders`) 걸을 수 있는 곳은 흰 널 줄뿐이다(`keyBridgeWalkable`; 검은 널은 흰 널 위에 서서 따로 열지 않는다). 그래서 다리는 북쪽 기슭에서 걸어 들어가고 서는 자리는 널 줄 윗변에서 200 px 위의 기슭이다. 그림의 물과 막힌 칸이 같은 사각형이라 보이지 않는 벽이 없다(설계서 3.8).
- **그림**: 물가 띠와 물과 옅은 물, 널 아래 물결 네 줄, 연잎(웅덩이마다 최대 여섯 장, 씨앗 `20261112 + x + y`, 널 줄에서 12 px 이상 떨어진 곳에만), 널 줄의 그림자, 흰 널(마을 돌과 같은 밝은 나무색, 아래쪽 그늘, 위쪽 못 둘), 검은 널(같은 나무를 어둡게, 그림자와 윤)이다(`PLANK_ART`). 널 그림은 바닥 그림의 길 위, 나무 그림자 아래에 얹는다.
- **반음 계단(K4)**: 돌 열세 개를 7개와 6개 두 줄로 꺾는다(설계서 4.3). 위 줄은 서는 자리 오른쪽 100 px에서 오른쪽으로 일곱 칸(돌 1–7, 첫 돌의 왼쪽 위 모서리 (900, 4560)), 아래 줄은 일곱째 칸 바로 밑에서 왼쪽으로 여섯 칸 돌아온다(돌 8–13, 첫 돌 (1494, 4743), `slotStart` 8, `dir` −1). 돌 81×153, 같은 줄 중심 간격 99 px, 7번에서 8번은 183 px다. 속 점의 색은 열세 개에 걸쳐 풀빛에서 볕빛으로 이어진다(`total` 13).
- **표지판**: K1–K3은 서는 자리에서 오른쪽 72 px, 위쪽 8 px에 서고 막는 자리가 있다(지도의 `sign-K1` (2372, 5092), `sign-K2` (1272, 5492), `sign-K3` (3272, 5592)). K4의 `sign-K4` (800, 4596)는 서는 자리 북쪽에 선다: 서는 자리 오른쪽 72 px의 기본 자리는 첫 돌의 틀에 닿는다.

### 길목 표지판 여섯(waysign-*, 7-7)

길 위 어디서든 다음 정거장이 보이거나 들려야 한다는 규칙 1(설계서 3.4)은 마을 밖 길 여럿이 600 px 넘게 비어서 어겼다. 처방인 표지판 여섯을 코드가 아니라 월드 원본(`world-src/regions/<지역>.tmj`)에 놓았다. 정거장 곁 표지판 18개와 같은 그림을 쓰는 소품(class `prop`)이다.

- **놓인 것**: 이름은 `waysign-<지역>-<번호>`, 그림은 `obj-<지역>-signpost`(마을 밖 지역 다섯의 파일이 있고 마을에는 없어서 마을 밖에만 놓는다), `ay` 0.9333, `blockR` 14. 종나무 숲 `waysign-bell-grove-1` (2064, 1314), 건반 늪 `waysign-key-marsh-1` (3802, 4610)과 `waysign-key-marsh-2` (3995, 4943), 박자 강가 `waysign-beat-river-1` (5709, 1247)과 `waysign-beat-river-2` (5764, 3657), 오선 언덕 `waysign-staff-hill-1` (2692, 1269).
- **정거장 곁 표지판(`sign`)과 다르다**: `sign`은 가리키는 정거장의 id(`station` 속성)가 꼭 있어야 하지만(`world-src/placements.ts`), `prop`인 길목 표지판에는 정거장이 없다. 그림과 막는 자리(반지름 14)뿐이라 누를 곳도 안내 칩도 없고, 길 위에서 눈에 들어오는 것이 일의 전부다. 같은 그림이고 윗띠의 색은 지역마다 다르다.
- **자리의 조건**(`tests/unit/world-sight.test.ts`가 읽는다): 길 가장자리에서 40–240 px, 지역 경계에서 100 px 넘게 안쪽, 둘레 72 px의 열두 곳이 걸어서 닿는 땅, 다른 사물 그림(나무 덮개 포함)에서 24 px 넘게, 설치물이 놓인 자리에서 100 px 넘게, 발견 요소와 정거장과 정거장의 서는 자리와 마을 사람의 자리에서 150 px 넘게 떨어짐. 어느 하나를 빼도 규칙 1이 깨진다는 것도 시험이 읽는다(군더더기가 없다).
- **왜 이 여섯인가**: 규칙 1은 길을 8 px 간격으로 훑어 자리마다 가운데 줄과 양쪽 가장자리(폭의 절반 옆)에서 정거장의 서명 소리(810 px 안), 기준음 탑의 소리(810 px), 표지판(270 px 안)이 하나라도 알아볼 수 있는지로 센다(`src/domain/roadsight.ts`). 발견 요소는 검수를 마치고 공개되기 전에는 공개 채널에서 보이지 않으므로(G2-7) 세지 않는 가장 나쁜 경우로 본다. 이때 길목 표지판 없이는 남쪽 바큇살(`spoke-south`)과 음계 길로 가는 바큇살(`spoke-scale`), 둘레길(`loop`)이 규칙을 어기고 가장 긴 빈 구간이 2,077 px이다(600 px를 넘는 구간 5곳). 여섯을 놓으면 584 px로 줄어든다(한도 600 px에 16 px 여유). 이 계산은 정거장의 서명 소리가 810 px까지 들린다는 것과 표지판이 270 px까지 보인다는 것(캐릭터가 화면 한가운데에 있을 때의 값이고, 카메라 멈춤 구역 때문에 세로 화면에서 걷는 쪽으로는 약 170 px까지 줄 수 있다)에 기대고, 소리를 켜지 않은 사람에게는 맞지 않는다(`docs/approvals.md`의 7-7 알려진 한계). 자리를 고른 계획 도구(가장 긴 빈 구간의 가운데 둘레에서 위 조건을 지키는 자리를 하나씩 골랐다)는 저장소 밖의 임시 도구라서 남기지 않았고 결과가 지도 파일에 있다. 자리를 다시 골라야 하면 같은 일을 손으로 하고, 맞는지는 시험과 `npm run roadsight`가 알려 준다.
- **월드의 숫자**: 사물은 160개에서 166개로(소품 12개에서 18개, 나무 130과 표지판 18은 그대로), 걸을 수 있는 칸은 42,862에서 42,842(전체 49,152)로, 바닥 해시는 `298267d76b26c8be`에서 `c8d808a3a597e22e`로 바뀌었다. `tests/unit/world-source.test.ts`의 기대값(소품 18, 사물 166)과 소품의 이름도 맞췄다.
- **바꾸는 법**: 표지판을 옮기거나 더하려면 지역의 `.tmj`에서 소품을 고치고(번호는 지도의 `nextobjectid`를 따른다) `npm run build:world`를 돌린다(`npm run validate`는 생성된 월드 데이터를 읽으므로 이 순서를 지킨다). 정거장이나 길을 옮기면 `npm run validate`(곧 `npm run build`)가 `ROAD_BARE` 문제로 어느 길의 어느 구간이 600 px를 넘는지 알려 준다. `npm run roadsight`는 길마다 빈 구간과 한도에 가까운 구간, 어림값을 바꿨을 때의 숫자를 찍는다(자리를 골라 주지는 않는다).
- **어긋나면**: `tests/unit/roadsight.test.ts`(계산, 27개)와 `tests/unit/world-sight.test.ts`(월드의 데이터, 23개)가 규칙 1과 2, 표지판의 자리, 걷는 시간을 잡고, 실제 Chrome `tests/flow/phase7-waysigns.flow.ts`가 여섯 표지판마다 길 위에서 보았을 때 그림의 색이 그 자리에 보이는지를 읽고 사진(`docs/verification/screens/phase7-waysign-*.png`)을 남긴다. 그림이 길 위에서 알아보기 쉬운지는 눈으로 보는 점검이다(사람 확인 대기).

## 그림을 칠하는 코드(햇살 과슈, D-308)

## 아틀라스

`world-src/atlas.ts`가 선반 방식으로 틀을 쌓고(키가 큰 순서, 틀 사이 4 px 비움, 가로 2048 이하, 가로는 2의 거듭제곱이고 세로는 16의 배수, D-291), `tools/atlas.ts`가 sharp로 2배로 칠해 WebP 한 장(`objects.webp`, 색은 품질 88의 손실 압축이고 투명도는 무손실, D-309)과 Phaser JSON Hash(`objects.json`)로 쓴다. `npm run build:atlas`로 그림만 다시 구울 수도 있다. 장면은 `this.load.atlas`로 한 번에 불러온다(낱장 SVG 26개 요청이 2개로 줄었다).
